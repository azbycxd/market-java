# V2-6B.1 规则知识与运行时能力边界修正

## 1. 为什么 `agent_facts_capability_boundary` 不属于 RAG

该条目描述的是某一时刻 Agent 注册了哪些查询能力。这是运行时能力信息，不是稳定的拼团业务规则。Tool 增减、描述或参数契约变化后，Catalog 中的静态描述会立即可能过期，并会与运行时的 `ToolRegistry`、`available_tools` 和 Observation/Evidence 职责边界产生冲突。

## 2. Runtime Capability 与 Business Knowledge 的区别

- **Runtime Capability**：当前 Agent 实际允许调用的 Tool、参数 schema 和描述。它必须由 Agent 的 `ToolRegistry` 生成并通过 `available_tools` 在每次运行时提供。
- **Business Knowledge**：从 Java 业务规则事实源整理出的稳定、可解释的一般拼团规则和状态语义。它可以被版本化 Catalog 检索，但不能告诉调用方当前注册了哪些 Tool。

因此 Runtime Capability 不应进入本 Catalog，也不能由检索结果替代运行时注册表。
