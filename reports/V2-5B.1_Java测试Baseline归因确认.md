## 4. 两个失败测试的真实失败点

### 4.1 `ITradeLockOrderServiceTest#test_lockMarketPayOrder`

baseline 结果：`Tests run: 1, Failures: 0, Errors: 1`。

调用参数使用 `userId=xiaofuge`、`activityId=100123`、`goodsId=9890001`、`outTradeNo=909000098111`。链路到达 `TradeLockOrderService.lockMarketPayOrder` 后，先执行 `UserTakeLimitRuleFilter`；日志明确记录“用户参与次数校验，已达可参与上限 activityId:100123”，随后抛出 `E0103`。

这发生在锁单持久化之前，未完成订单写入。它是对固定活动/用户历史数据有依赖的集成测试，且测试本身未隔离数据。

当前 V2-5B 后全量套件报出的同一 E0103 位于相同既有链路：

```text
UserTakeLimitRuleFilter.apply
  -> TradeLockOrderService.lockMarketPayOrder
  -> ITradeLockOrderServiceTest.test_lockMarketPayOrder
```

不存在 V2-5B 新类或新增 Agent API 的栈帧。

### 4.2 `IIndexGroupBuyMarketServiceTest#test_indexMarketTrial_error`

baseline 结果：`Tests run: 3, Failures: 0, Errors: 1`，其中 `test_indexMarketTrial_error` 为唯一 error。

该测试以 `goodsId=9890002` 调用已有的市场试算服务。日志显示：`商品无拼团营销配置 9890002`，既有 `ErrorNode` 抛出 `E0002`。测试方法未声明或断言这是预期业务异常，因此 Surefire 将它计为 error。

链路为：

```text
ErrorNode.doApply
  -> 既有市场策略节点链
  -> IndexGroupBuyMarketServiceImpl.indexMarketTrial
  -> IIndexGroupBuyMarketServiceTest.test_indexMarketTrial_error
```

同一基线测试的另外两个场景可执行；只有依赖不存在营销配置的 `9890002` 场景失败。当前 V2-5B 后的 E0002 与基线完全一致，且无 V2-5B 新类栈帧。

## 5. ApiTest 卡住情况

本阶段未动态执行 baseline `ApiTest`，原因是其源码在 baseline 中已包含不可安全用于“只诊断”运行的副作用：

- `test_rabbitmq` 向 `topic_team_success` 发布 5 条消息；
- 随后调用没有释放路径的 `CountDownLatch.await()`，可无限等待；
- 其他方法还包含 Redis 锁和 sleep。

当前全量运行在两项既有 error 后到达该类时没有产生有效 Surefire 完成结果，符合该测试原有的无限等待设计。因为动态执行会发送真实 RabbitMQ 消息，违反本次“不修改数据/不产生业务写操作”的诊断边界，故未以强制终止方式再次运行。该项为既有测试可运行性问题，不能作为 V2-5B 回归证据。

## 6. 是否进入 V2-5B 新增代码

否。

V2-5B 新增调用链限定为 `AgentJoinableTeamFactsController` → `IAgentJoinableTeamFactsService` / `AgentJoinableTeamFactsService` → 现有 `IIndexGroupBuyMarketService` 的只读查询。两个失败测试均直接调用既有交易锁单/市场试算服务；V2-5B 未改动它们的接口、实现、Mapper、原测试或 SQL 初始化脚本。更直接地说，隔离的 pre-V2-5B 基线源码根本不含这些新增 Agent 类，却仍复现同样错误。

## 7. 归因与后续准入

- E0103：既有活动用户参与次数上限的数据依赖。
- E0002：既有测试数据中 `9890002` 没有拼团营销配置，且测试未将该异常作为断言预期。
- ApiTest：既有的 MQ 副作用 + 无界等待，导致全量套件无法可靠收敛。

这些问题不应否定 V2-5B 的功能验收。全量基线保持 RED，后续应以独立的测试隔离/固定数据改造任务处理，而不应在本阶段修改老测试、活动数据或基础设施状态。
